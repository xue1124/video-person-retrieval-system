# 模型部署面试准备

## 可以讲清楚的主线

项目先保留 PyTorch 权重，再导出 ONNX 作为通用中间格式。NVIDIA GPU 使用 TensorRT Engine，瑞芯微设备使用 RKNN。转换的价值是利用目标硬件的算子优化和低精度计算降低延迟、提高吞吐量。

## 常见追问

1. **为什么需要 ONNX？** 训练框架和部署硬件不同，ONNX 用统一计算图连接二者。
2. **为什么 Engine 不能随便复制到另一台机器？** 它与GPU架构、TensorRT、CUDA和构建参数有关，通常要在目标环境重新生成。
3. **动态输入和静态输入有什么区别？** 动态模型适应不同 batch/尺寸；静态模型更容易针对固定输入优化，嵌入式转换也通常要求更明确的形状。
4. **FP32、FP16、INT8怎么选？** 精度越低通常越快、占用越小，但要用真实样本验证误差；INT8一般需要有代表性的校准数据。
5. **转换后结果不一致怎么排查？** 依次核对尺寸、RGB/BGR、归一化、NCHW/NHWC、输出节点、NMS、特征归一化和数值精度。
6. **怎么证明优化有效？** 在相同硬件、相同输入和预热条件下，对比准确率或检索结果、单次延迟、FPS、吞吐量和资源占用。
7. **OSNet为什么有多个Engine？** 动态 batch 1–8、1–16适合不同批量吞吐；静态 batch 1适合低延迟单图推理。选择要结合实际并发和显存。

## 需要诚实说明的范围

本仓库保留了 OSNet 的 RKNN 转换脚本和各类部署产物。YOLO/SigLIP 的部分产物存在，但完整转换日志与所有构建脚本没有全部保留。因此面试时可以讲部署思路、实际运行格式和验证方法，不应声称每个文件都从头手写转换工具。

仓库中的 `deployment/export_yolo.py` 是统一的YOLO导出入口，`deployment/rknn/convert_osnet.py` 是OSNet转RKNN入口。转换命令只是第一步，真正能体现部署能力的是在目标硬件上完成兼容性验证和指标对比。
